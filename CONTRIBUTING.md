# Contributing to FlowLocal

Thanks for helping out! This project follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development setup

1. Install [Rust via rustup](https://rustup.rs) (the toolchain is pinned in `rust-toolchain.toml` and includes `rustfmt` and `clippy`).
2. Install Node.js 20 or newer.
3. Install the [Tauri 2 platform prerequisites](https://tauri.app/start/prerequisites/). On Ubuntu:
   `sudo apt-get install -y libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev libasound2-dev libxdo-dev libxtst-dev libxi-dev cmake clang`
4. Fork and clone, then:

```bash
npm ci
npm run tauri dev
```

macOS is the best-tested platform. If you change platform-specific code (`cfg(target_os = ...)`), say in the PR which OSes you actually ran it on; CI builds all four targets but does not exercise global hotkeys or paste.

## Workflow

1. Fork the repo and create a branch from `main` (`feat/short-name`, `fix/short-name`, `docs/short-name`).
2. Make focused changes. Open an issue first for anything large.
3. Run the checks below locally.
4. Push to your fork and open a pull request against `main`. Fill in the PR template.
5. A maintainer reviews; CI must be green. PRs are squash-merged, so the PR title becomes the commit message.

### Commit and PR titles: Conventional Commits

Use [Conventional Commits](https://www.conventionalcommits.org): `type(scope): summary`.
Types: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `build`, `ci`, `chore`.
Examples: `feat(models): add Moonshine tiny to catalog`, `fix(insert): restore image clipboard`.

## Tests come first

We expect test-driven development: write the failing test, watch it fail, then make it pass.

- Rust logic is unit-tested; the dictation state machine, chunk planner, downloader and post-processing are designed to be testable with fakes and no audio, models or OS hooks. Add tests next to the code (`#[cfg(test)]`) or in `src-tauri/src/*/tests.rs`.
- Frontend behavior is tested with Vitest and Testing Library (`src/**/*.test.ts(x)`).
- A bug fix should come with a test that fails without the fix.
- Real-model tests are `#[ignore]`d; see "Running tests" in the README.

## Checks to run before pushing

```bash
cd src-tauri
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cd ..
npx tsc --noEmit
npx vitest run
```

Run `cargo fmt` to fix formatting. Warnings are errors in CI.

## Adding a model to the catalog

The catalog is `src-tauri/resources/catalog.json`, generated by `scripts/build_catalog.py` (Python 3, standard library only; needs internet).

1. Find the sherpa-onnx repo on Hugging Face (usually under `csukuangfj/`) and confirm which engine it uses (`transducer`, `whisper`, `moonshine` or `sensevoice`) and which int8 files it needs.
2. Add an entry to the `MODELS` list in `scripts/build_catalog.py` (id, display name, repo, engine, file list, languages, minimum RAM, notes), following the existing entries.
3. Regenerate: `python3 scripts/build_catalog.py > src-tauri/resources/catalog.json`. The script pins the repo's current commit and resolves each file's size and SHA-256 from the Hugging Face API.
4. Run `cargo test` (the catalog parsing tests must pass) and check the model appears in the Models page.
5. If you can, actually download it in the app and dictate with it. Say in the PR which model you tested and on which OS.
6. Update the model table in `README.md`.

You can also use the model request issue template if you would like a maintainer to look at one.
